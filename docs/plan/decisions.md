# Technical decisions

Each row becomes a short ADR in `docs/adr/` (context, decision, consequences; at most one page). The ADRs are written in task 12.4.

| ADR | Decision | Why | Rejected alternatives |
|---|---|---|---|
| 0001 | pnpm workspaces monorepo: `apps/web`, `packages/api`, `packages/shared`. No Turborepo/Nx. Internal packages export TypeScript sources (`"exports": "./src/index.ts"`); Next compiles them through `transpilePackages`. | One repo, one install, shared types. Three packages do not need a task runner. No build step for packages. | Turborepo (caching not needed at this size); Nx (heavy); separate repos (type drift). |
| 0002 | GraphQL API as a framework-agnostic package, mounted in Next.js as the route handler `/api/graphql`; also runs standalone. | Same origin: no CORS, one preview per PR, one Sentry project, no Deployment Protection bypass. A clean package boundary keeps the backend separable. | Second Vercel project (CORS, preview URL coordination); API code inside `app/` (no boundary). |
| 0003 | Schema-first SDL + GraphQL Codegen: client preset (typed documents) + `typescript-resolvers` with Prisma model mappers. | Types flow end to end: DB → resolvers → operations → components. | Code-first (Pothos): fine too, but SDL is easier to review and to document. |
| 0004 | State: Apollo cache for server state, URL for shareable view state, a reducer for queue interaction, localStorage for preferences. No Redux. | Each piece of state has one owner; nothing is duplicated; deep links work. | Redux Toolkit / Zustand (would duplicate the Apollo cache). |
| 0005 | Console data is fetched in the browser; the server renders shells and fixed-size skeletons. | An internal tool with per-moderator, fast-changing data; simple and reliable. LCP is guarded by Lighthouse CI. Upgrade path: N3 streaming SSR with `PreloadQuery`. | SSR of every query from day 1 (more moving parts on a critical path). |
| 0006 | Optimistic moderation: `optimisticResponse` + cache helpers; batch-based undo with item snapshots; server conflict detection with `UPDATE … WHERE status = 'PENDING' RETURNING`. | Instant UI, correct under concurrency, one undo for a bulk action. | Refetching after each action (slow, focus jumps); version columns (not needed). |
| 0007 | Keyboard model: ARIA listbox + roving tabindex, one global `useHotkeys` hook with a shortcut registry, focus rules in a pure reducer, a setting that turns single-key shortcuts off (WCAG 2.1.4). | Predictable for screen readers; testable without a browser; one source for the help dialog. | `role="grid"` (more complex, no gain); a hotkeys library (less control over ignore rules). |
| 0008 | Our own UI kit on Radix primitives + Tailwind v4 tokens (CSS variables) + `cva`. | Accessible behaviour from Radix, the look from our tokens, a small API that we control. Dark mode is only a second set of token values. | shadcn/ui copy-paste (more code than this app needs, and its styling conventions instead of ours); MUI (heavy, hard to theme). |
| 0009 | Polling for live updates (N1), not SSE or WebSockets. | Serverless functions do not hold connections; 15 s polling of a small query is enough for a mod queue. | SSE on Vercel (duration limits); a WebSocket service (extra infrastructure). |
| 0010 | Testing pyramid: pure functions (Jest) → API integration against real Postgres → components (RTL + MSW + jest-axe) → a few Playwright journeys on three viewports. | Fast feedback where the logic is; real browser only where it matters (focus, layout, performance). | Mocking Prisma (misses SQL bugs); E2E for everything (slow, flaky). |

Smaller decisions (no ADR needed): kebab-case file names (case-insensitive file systems on Windows/macOS); Radix through the unified `radix-ui` package; `lucide-react` icons; `next/font` for Inter; native `<select>` and `<input type="date">` where they are good enough; `Intl` for dates and numbers (no date library); `@faker-js/faker` with a fixed seed for the data; `dataloader` against N+1; time-released reports instead of a traffic simulator ([api.md](api.md)).
